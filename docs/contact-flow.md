# Contact flow operations

The `/contact` page and `POST /api/contact` share one Worker handler. Agents may submit JSON only with the user's permission. The endpoint accepts form-encoded browser requests too. Browser requests with an `Origin` header must come from `https://finopsllm.com`; originless agent clients are allowed. It sends plain-text email to the fixed recipient `hello@finopsllm.com`; the submitted address is used only as `replyTo`. Validation, an 8 KiB body cap, a honeypot, and the `CONTACT_LIMIT` binding guard delivery. The limiter allows five attempts per minute per Cloudflare location and IP; shared networks can hit the same limit.

Before publishing, onboard `finopsllm.com` as an Email Service sending domain, verify the recipient address in Cloudflare Email Routing, and confirm that `contact@finopsllm.com` is permitted as the sender. The `send_email` binding in `wrangler.jsonc` restricts both sender and recipient. The domain has MX records, but end-to-end delivery has not been verified. Send a controlled test after the bindings are active and check the receiving inbox and Worker email logs. If either the email or rate-limit binding is unavailable, the API responds `503` without accepting the request. Form submissions without JavaScript receive fixed HTML responses and a fixed success redirect. Do not treat the honeypot's success response as delivery.

Existing Tidal users sign in at `https://openlit.llmcfo.com/login`. Company enrollment and invitations are being prepared for a separate Tidal rollout; they are not issued by this marketing site. Route access requests to the operator through the contact flow; do not promise immediate account creation or a live enrollment link. No Tidal credentials or customer billing data should be submitted in contact messages.
